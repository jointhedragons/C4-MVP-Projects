# AI Schedule Planner MVP v2.0 - Rules & Constraints

## Core Rules

### 1. Rule-Based Engine First
- **Always compute rule-based results first** before any AI processing
- Rule-based engine finds exact overlapping time slots
- If no perfect overlap exists, return partial overlaps
- Never skip the rule-based validation step

### 2. Multi-Meeting Optimization
- **Priority-based scheduling** - always prioritize high-importance meetings
- Use greedy algorithm for fast optimization, genetic algorithm for complex scenarios
- Detect and resolve conflicts (time, participant, resource)
- Maximize total number of meetings that can be scheduled
- Support overlapping team members across multiple meetings

### 3. AI Layer Validation
- **Never trust Gemini blindly** - always validate AI results against input availability
- AI suggestions must be validated against original team availability
- Invalid AI suggestions should be rejected and fall back to rule-based results
- Gemini must output strict JSON format (no extra text or markdown)
- Enhanced prompts for multi-meeting scenarios

### 4. Fallback Strategy
- **Always return a fallback from rule-based** if Gemini fails
- If AI processing fails, continue with rule-based results
- Never return empty results if rule-based engine found valid slots
- Log AI failures but don't expose them to users

## Project-Specific Rules
- Use the naming convention: `Ahmed Khaled Abdel Fattah_AI-Schedule-Planner_4_PROJ-D`
- All commits must use format: `[PROJ-D] Description of changes`
- Follow the three-day MVP constraints
- Focus on multi-meeting optimization capabilities

## Technology Stack Constraints

### Backend (Node.js + Express)
- Use Node.js + Express for API server
- All API responses must be in JSON format
- Implement proper error handling and validation
- Use CORS for frontend communication
- Rate limiting on API endpoints (basic implementation)
- **No database for MVP** - keep everything in memory
- Use in-memory JSON storage for all data

### Frontend (React + TailwindCSS)
- Use React + TailwindCSS for UI
- Keep UI minimal and clean
- Responsive design for mobile and desktop
- Real-time validation of JSON input
- Clear error messages for users

### AI Integration
- Use Google Gemini API for AI refinement
- Validate all AI responses before using them
- Implement proper error handling for API failures
- Use structured prompts for consistent output
- Parse and validate JSON responses strictly

## MVP Limitations
- Maximum 10 team members
- UTC timezone only
- 15-minute time slot granularity
- No calendar integration
- No persistent storage
- No user authentication

## Security & Validation
- Validate all user input (timezones, time slots)
- Sanitize JSON input to prevent injection
- Validate time format (HH:mm)
- Check that start time < end time
- No secrets in repository (use .env files)
- Basic rate limiting on backend routes
